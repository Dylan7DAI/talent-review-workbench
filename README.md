# 研判 · AI 人才潜力初评助手

一套面向 AI / 大模型青年学者与技术人才的中文初筛工作台，基于 Next.js + 智谱 GLM 构建。首次打开即可零门槛浏览十份博士简历的实测快照；接入智谱 API Key 后可对任意 Markdown 简历集执行实时盲审、权重重排、证据溯源与报告导出。

---

## 一、快速使用

### 1. 本机手动启动
环境要求：**Node.js 24**、**npm 11**。在项目根目录运行：

```sh
npm ci
npm run dev
```

浏览器打开 <http://127.0.0.1:3000> 即可使用。

### 2. 一键交给 AI 启动
如果你使用 Claude Code、Codex、Cursor、Antigravity 等 AI 编程助手，可以直接在项目目录中把下面这段话发给 AI，由它帮你完成环境检查与启动：

> 请帮我启动当前目录下的 Next.js 项目并给我可访问的本地网页地址：先检查 `node -v` 与 `npm -v`（推荐 Node.js 24 / npm 11），若缺少 `node_modules` 则执行 `npm ci`，然后在后台启动 `npm run dev`（监听 `http://127.0.0.1:3000`），确认服务 `Ready` 后把链接发给我。注意：① 确保服务运行在本机浏览器可访问的环境中（如在沙盒中无法被宿主机浏览器访问，请在沙盒外启动）；② 启动 `next dev` 后不要再执行 `npm run build`，避免覆盖 `.next` 导致页面样式丢失；③ 首次打开可直接浏览内置快照，如需实时重跑我会在页面「模型」设置中输入 Key，请勿索要、打印或提交任何 `.env.local` 密钥。

**AI 执行速查（Agent Spec）**：
- **工作目录**：仓库根目录（含 `package.json`）
- **安装依赖**：`npm ci`（仅当 `node_modules` 不存在时）
- **启动服务**：`npm run dev`（守护进程，监听 `127.0.0.1:3000`）
- **就绪判据**：日志输出 `Ready in ...` 且 `http://127.0.0.1:3000` 可访问
- **避坑约束**：勿与 `npm run build` 并发/混跑；勿读取或输出 `.env.local` 中的密钥内容

### 3. 配置智谱 API Key（如需实时重跑）
首次打开会直接展示内置的十人实测快照，无需 Key 即可体验全部交互。如需实时调用智谱 GLM 重跑，支持两种方式：
- **页面输入（推荐）**：点击顶部「模型」，填入智谱 API Key（仅保留在当前页面内存中，不落盘）。
- **本地环境变量**：将根目录的 [.env.example](.env.example) 复制为 `.env.local`，填写 `OPENAI_API_KEY`（也支持 `ZHIPU_API_KEY`）后重启开发服务器。

> 项目使用 `LLM_MODE=api` 与智谱标准端点 `https://open.bigmodel.cn/api/paas/v4`，默认模型为 `glm-4.5`（可在页面「模型」或环境变量 `GLM_MODEL` 中切换）。公网部署（如 Vercel）强制走 BYOK 模式，仅本机回环开发服务允许读取 `.env.local`。

### 4. 上手流程
1. **导入简历**：点击「数据源」上传自定义 `.md/.txt`、粘贴文本，或一键读取内置附件 `src/data/10_ai_phd_resumes.md`。页面会即时显示解析人数与异常记录。
2. **运行初评**：点击「运行全量初评」。系统按两路并发逐人调用智谱 GLM，实时展示耗时、进度与单人失败重试，已完成项自动写入浏览器缓存；整批完成后自动生成 150–280 字的批次横向洞察（覆盖各梯队编号）。
3. **权重推演与档案核验**：在总览拖动四维权重滑块，毫秒级重算综合分、排序表与二维象限落位（调权后可点击更新洞察）。点击表中编号或象限气泡进入深度评审台，直接查看推进建议、面谈追问、两周培养计划及逐条原文行号引文。
4. **导出与回退**：点击「导出」下载 Markdown 评审报告或 JSON 快照；随时可通过「数据源 → 加载实测快照」切回内置十人基准结果。

### 5. 输入规范与容错边界
- 单批支持 **1–20 份简历**，UTF-8 文本上限 **100 KB**；推荐每人以 `## 候选人 01｜研究方向` 开头。
- 面对空文本、超长/非 UTF-8 文件、缺失栏目、非标准标题、重复编号或全零权重，系统均不崩溃，而是通过多级回退解析、告警提示与单人错误隔离稳健处理。

## 二、项目介绍

### 1. 设计目标与核心评估观
本工具的目标**不是**传统招聘中的关键词匹配或学历排序，而是围绕**「研究品味（Research Taste）与归因能力」**，识别真正具备长期成长潜力、值得持续培养的研究与工程人才：
- **真盲审去光环**：在送入模型前，由确定性代码物理剥离学校层级、GPA、CCF-A/B 发表状态、大厂/机构名等光环信息，仅保留实践正文与预检信号；盲审完成后再由代码对照光环与实证分，自动标记「逆光环高潜」或触发「光环与实证有差距」补问。
- **有分必有据**：每个有分维度必须绑定可在该人实践原文中逐字匹配的引文编号，并在界面自动映射为原文行号，方便面谈前复读上下文。

### 2. 四维 BARS 评估维度与默认权重

| 维度 | 默认权重 | 优先核实的行为证据 |
| :--- | ---: | :--- |
| **归因与研究品味** (`attribution`) | 30% | 是否追问“为什么有效”、做误差归类/机理定位/基线对照并交代收益边界 |
| **独立问题定义** (`problem_formulation`) | 25% | 脱离成熟流水线后，能否发现被忽视的真痛点并界定可检验目标 |
| **工程与实验迭代** (`engineering_velocity`) | 25% | 自建诊断/自动化工具、开源上游合入、持续维护与真实多用户复用 |
| **数据与 Scaling 直觉** (`data_scaling`) | 20% | 数据质控抽检、标注一致性复核、按难度分桶或跨规模验证 |

### 3. 算分、护栏与分层口径
- **0–5 离散锚定**：`0` 表示证据不足（引文必为空，不惩罚总分但拉低置信度）；`1` 表示明确反信号；`2–5` 对应表层执行、合格闭环、扎实优秀与顶尖标杆。
- **归一化加权与封顶**：代码仅对有效维度（> 0 分）归一化加权映射为百分制；有效维度不足 2 项时综合分封顶 65 分；四维全零时自动回退默认权重。
- **单点尖峰保护（`◎` 双环）**：任一核心维度达到 5 分且综合分 ≥ 60 时，破格进入 **A+**，防止“0 论文但工程极强”的偏科人才被均分埋没。
- **沟通分层（S / A+ / B / C）**：
  - 材料稀疏或有效维度 < 2 优先归为 **B（补问后定）**；
  - 其余候选人中：非低置信度且 ≥ 80 为 **S（强烈推荐推进）**；非低置信度且 ≥ 70 或触发单点尖峰且 ≥ 60 为 **A+（建议推进）**；低置信度（`◌` 虚线环）、触发光环反差或 ≥ 65 为 **B**；其余为 **C（暂缓推进）**。

### 4. 十份附件实测快照与交付物
当前内置快照结果为 **S 1 人（`02`）、A+ 5 人（`05`、`06`、`07`、`04`、`08`）、B 4 人（`09`、`03`、`01`、`10`）、C 0 人**，高潜梯队（65–80 分）与待核验尾部（20–49 分）拉开 **16 分以上断层**：
- `02` 四维均为 4 分（综合 80 分），凭可验证数据合成与难度分桶对照稳居 **S** 档逆光环标杆；
- `08` 虽无正式发表论文，凭多课题组日常使用与开源维护获工程 5 分、综合 65 分，触发单点尖峰进入 **A+**；
- `05`、`06`、`07`、`04` 均凭扎实的机理定位、评测闭环或工程交付稳居 **A+**（70–71 分）；
- `09` 材料稀疏且存在重复表述，保留在 **B** 档低置信；`01`、`03`、`10` 均落于末段并自动生成核验追问。

| 项目交付物 | 说明 |
| :--- | :--- |
| [十人实测报告](outputs/初评报告.md) | 最新快照导出的完整分层、批次洞察、逐人建议、追问及原文证据 |
| [完整评估快照](src/data/verified-snapshot.json) | 页面默认加载的结构化实测快照，可用于核验与复现 |

| 思路复盘与操作演示 | 完整设计复盘（含评估体系、AI 协作截图、Prompt 迭代对比与三人详析）及录屏演示见同步提交的飞书文档 |

## 三、开发过程与工程细节

### 1. 混合架构与核心模块
为适配智谱 GLM 的能力边界，项目将**语义判断**与**确定性计算**彻底解耦：
- `src/lib/parser.ts`：Markdown 多级容错解析、光环信息脱敏（`redactHaloFromText`）与稀疏/重复/模糊词预检。
- `src/lib/evidence.ts`：将脱敏正文切分为 `E1..En` 证据编号并在展示层映射回「原文第 X 行」，防止引文幻觉与内部编号泄露。
- `src/lib/prompts.ts` & `src/lib/glm.ts`：定义盲审评分提示词（`barsPrompt`）、批次洞察提示词（`summaryPrompt`）、智谱 API 通信（显式关闭 `glm-4.5` 思考模式以防超时截断）、Zod 校验、引文存在性校验与带反馈的单次自动重试。
- `src/lib/scoring.ts`：确定性算分、置信度、单点尖峰、光环反差、四级分层与二维象限坐标计算。
- `src/app/api/*`：薄代理路由（`evaluate`、`summary`、`resumes/default`），提供同源检查、100 KB 流式截断与统一错误处理。
- `src/components/*`：评审台界面（`Workbench`、`TopControlBar`、`BatchOverview`、`QuadrantChart`、`CandidateDossier`）。

### 2. 关键工程与体验迭代
1. **盲审 Prompt 重构（`blind-bars-5` → `blind-bars-6`）**：在保持 `temperature: 0.2` 不变的前提下，将分散的补丁式提示词重构为 5 个清晰区块，明确划清 `0（缺证）/ 1（反信号）/ 2（表层执行）` 硬边界，实测消除了早期对 `04`/`05`/`06`/`08` 的 4 处红旗误报，并将 `05`、`07` 稳定校准回 A+ 梯队。
2. **批次洞察结构化与全员覆盖**：将 `summaryPrompt` 固定为四步紧凑成段结构，强制按梯队写出全部候选人编号，并将代码长度校验放宽至 `150–280` 字符，消除踩边重试与漏编号问题。
3. **三轮界面审美与可读性精修**：确立「暖纸白阅读层 `#F7F6F2`/`#FFFFFF` × 苹果克制毛玻璃操控层 `blur(14px)`」材质分层；先后补齐象限图重叠气泡螺旋避让与牵引线、E 编号转原文行号、390px 移动端适配，并在第三轮将候选人页首屏拥挤的三窄列重构为「单张实体白卡：顶部通栏推进结论 + 下方 1:1 对称双栏 + 等宽编号对齐」，显著提升中文长文本阅读体验。

### 3. 开发、测试与快照复现

```sh
npm test          # 运行 26 项 Vitest 单元测试（解析、算分、GLM 校验与重试、API、导出）
npm run typecheck # TypeScript 静态类型检查
npm run build     # Next.js 生产构建
npm start         # 启动生产服务
```

- **CLI 快照生成**：运行 `npm run snapshot` 会读取本地 `.env.local`，按两路并发评估内置附件，并将单人结果按 `PROMPT_VERSION + model + markdown` 哈希缓存在 `.cache/` 中；完整批次通过校验后原子写入 `src/data/verified-snapshot.json` 与 `outputs/初评报告.md`。
